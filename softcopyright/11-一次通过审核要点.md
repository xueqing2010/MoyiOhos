## 一、审查最常看什么

| 常见问题 | 本项目对应处理 |
|---|---|
| 文档与源程序内容不符 | 说明书附录 D 按模块说明架构、接口、算法；源程序样本已改为优先展示 PageTranslateService、LocalOcrEngine、OverlayRenderer、ReaderPage、ocr_bridge 等核心代码 |
| 源程序像通用框架，缺少核心功能 | 源程序前 30 页优先放核心业务代码；不是只放 Ability/工具类 |
| 源程序最后一页没有完整结束 | 已把 ocr_bridge.cpp 放在样本末尾；最后一行是完整模块的结尾 |
| 说明书太简单，像模板 | 已扩充操作步骤、界面按钮说明、设计说明、数据流程、算法、异常处理，17 页 |
| 截图不真实/拼凑 | 使用开发调试版本真实截图；截图中的界面为墨译阅读/翻译/模型管理页面 |
| 软件名称/版本前后不一致 | 申请表、说明书封面/页眉、源程序页眉统一为“墨译漫画小说智能翻译软件 V1.1.0” |
| 编程语言填写不全 | 申请表填写 ArkTS、C++；源程序样本包含 .ets、.cpp、.h |
| 主要功能/技术特点与文档不一致 | 00 申请信息表、说明书第 4 章、附录 D 使用同一套功能描述 |
| 升级/重复申请 | 本软件为首次申请，未登记过低版本；不勾选“修改/原登记号” |
| 签章页无签章 | 系统生成后必须由薛朝坤本人签字并扫描上传 |
| 文档/源程序含敏感信息 | 已移除 API Key、密码、内网地址；身份证/联系方式只在系统填写，不放入材料 |

## 三、补正应对

如果收到补正通知，不要直接重新提交同一份材料，按通知逐条修改：

1. 文档与源程序不符：把补正提到的功能在说明书和源代码中同时补充；
2. 源程序缺少核心代码：把对应模块的核心服务/算法代码放入前 30 页；
3. 最后一页不完整：调整样本截取位置，让最后一行是函数/类的完整结束；
4. 文档不详细：补充界面按钮、操作步骤、模块/接口/算法说明；
5. 签名/身份问题：补签、补身份证扫描件；
6. 名称/版本不一致：统一修改后重新导出 PDF。

补正期限：自通知发出之日起 30 日内；逾期未补正视为撤回。
